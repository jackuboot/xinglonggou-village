# 03 · 角色与权限

> 职责范围：`dashboard/src/core/roles.js`、`db.js`、`cloudfunctions/roles-admin/`、授权相关 UI（`src/apps/admin/pages/AdminUsersPage.vue`）。

## 五角色模型（roles.js 为唯一数据源）

角色标识同时被前端代码与数据库 `user_roles.roles` 字段使用，改动必须两处一致：

| 角色 | 标识 | 职责 | 获取方式 |
| --- | --- | --- | --- |
| 农户 | `farmer` | 生产和提供服务 | 管理后台授权 |
| 入库员 | `keeper` | 农产品入库与代理发布 | 管理后台授权 |
| 消费者 | `consumer` | 预约、使用、跟踪 | **隐式默认**，所有登录用户自动拥有，无需授权 |
| 审计员 | `auditor` | 独立审计与数据核查 | 管理后台授权 |
| 管理后台 | `admin` | 用户授权与系统管理 | 管理后台授权 / bootstrap |

关键规则：

- 可授权角色集合为 `farmer / keeper / auditor / admin`（consumer 除外），前后端共用此约定。
- 支持一人多角色（roles 数组）；`effectiveRoles()` 计算有效角色：数据库授权 + 隐式 consumer，按 生产→记录→使用→审计 闭环顺序排序，admin 恒在末尾。
- 所有授权写操作只经管理后台「用户授权管理」页 → 云函数 `roles-admin`。

## 存储模型

- CloudBase 环境**自带 PostgreSQL**，表 `user_roles`（由云函数自动创建维护，幂等 `CREATE TABLE IF NOT EXISTS`）：`uid text PK`、`roles jsonb`、`name text`、`created_at/updated_at timestamptz`。
- 该表**未对 anon / authenticated 授权**，前端无法直接访问——读写全部经云函数。因此无需在控制台建集合、配权限规则。

## 云函数 roles-admin（cloudfunctions/roles-admin/）

安全设计三原则：

1. **身份只信云函数上下文的 `TCB_UUID`**，客户端传参一律不可信。
2. 所有授权写操作走 SQL 管理员通道（manager-node 的 `ExecutePGSql`），SQL 拼接值必须经 `esc()` 转义。
3. 前端异常兜底最低权限：`db.js` 的 `getGrantedRoles()` 任何异常（无记录/库未开通/调用失败）一律返回 `[]`，绝不放大权限。

Actions 一览：

| action | 权限 | 作用 |
| --- | --- | --- |
| `me` | 任何登录用户 | 返回调用者本人的授权（前端唯一读取通道） |
| `status` | 任何登录用户 | 系统状态（用户总数 / 是否已有管理员 / 是否首次运行等） |
| `bootstrap` | 仅部署端（CLI 调用，无用户上下文） | 授予首位 admin，双重准入：带用户上下文（uid 非空）的调用一律拒绝（防应用内自封管理员）+ **仅当系统尚无管理员时生效** |
| `list` | admin | 列出全部授权记录 |
| `grant` | admin | upsert 授权 `{ uid, roles, name }` |
| `revoke` | admin | 删除授权记录 `{ uid }` |

管理端写操作（list/grant/revoke）双重校验调用者确为 admin；`grant` 允许给自己追加角色但必须保留 admin（防自锁），`revoke` 禁止对自己执行（防误撤）。

## 首位超级管理员（bootstrap）

部署脚本 `deploy.ps1` 末尾交互式输入超管手机号，调用 `node scripts/set-super-admin.mjs <手机号>`；也可事后补设。仅首次（系统中无任何 admin 时）生效。

## 已知边界

- `me` / `list` 经 `readAll` 全量读取（`SELECT ... LIMIT 200`）后在函数内过滤：用户数逼近 200 时授权列表会截断，`me` 亦可能因本人记录排在 200 条之外读不到而静默降级为消费者——规模增长后的已知上限，当前规模无碍。
- 短信下发、验证码校验、未注册手机号自动建号均为 CloudBase 身份验证平台侧行为，仓库内仅有调用点与错误翻译文案。
- 登录与授权端到端时序图（含逐段代码证据与风险清单）见 `docs/architecture/`：[login-auth-flow.puml](../architecture/login-auth-flow.puml)、[admin-auth-flow.puml](../architecture/admin-auth-flow.puml)、[flow-evidence.md](../architecture/flow-evidence.md)、[flow-risks-and-gaps.md](../architecture/flow-risks-and-gaps.md)。
