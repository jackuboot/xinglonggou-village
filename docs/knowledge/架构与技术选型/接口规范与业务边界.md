# 接口规范与业务边界（v1.0）

> 核心原则：**云函数内部严格遵循 CloudBase 云函数规范；非云函数的外部接口才使用世界通行的 REST/OpenAPI/MCP 规范。适配层只做协议转换，不承载业务。**
> 本文件是接口设计的唯一权威；与旧文档冲突时以本文件为准。

## 一、范围划分（先分清，再设计）

| 范围 | 适用对象 | 必须遵循 | 禁止 |
| --- | --- | --- | --- |
| A. 云函数（callFunction） | 前端调用 CloudBase 云函数 | `exports.main(event, context)`；`event.action`；上下文身份；项目返回包 | 在云函数内部模拟 REST 路径/方法/状态码 |
| B. HTTP 触发云函数 | CloudBase HTTP 访问服务 | HTTP 事件结构（path/httpMethod/headers/body/query）；HTTP 状态码与响应体 | 把 HTTP 事件与 callFunction 事件混用 |
| C. 外部 REST API | 外部系统、开放平台 | OpenAPI 3.1；`/api/v1`；标准方法与状态码；problem+json | 暴露 `action` 字段、云函数名、内部错误细节 |
| D. MCP | Agent / 第三方工具 | MCP 工具 schema（JSON Schema）；工具名 `<domain>.<verb>`；权限与限流 | 把云函数 event 结构直接当 MCP 参数 |
| E. Agent function calling | 模型调用内部能力 | JSON Schema；副作用标注；白名单；审批 | 让模型直连数据库或绕过工具网关 |
| F. Webhook | 第三方回调 | HMAC 签名；重试；幂等；事件 ID | 明文密钥、无签名校验 |

> A/B 是同一业务契约的两种触发方式；C/D/E 是同一契约的不同传输适配器。**业务逻辑只写一份，放在 `domain/application`。**

## 二、业务范围（Bounded Context）

| 业务域 | 能力 | 主责角色 | 数据范围 | 写操作 | 暴露面 |
| --- | --- | --- | --- | --- | --- |
| 身份与授权 | 角色查询、授予、撤销、bootstrap | admin / 系统 | `user_roles` | 是 | 云函数（外部 HTTP 可选） |
| 农户资源 | 地块/产品/服务提交与修改 | farmer | 本人行级数据 | 是 | 云函数；Agent 经工具网关 |
| 入库与批次 | 入库、质检、批次登记 | keeper | 本村数据 | 是 | 云函数 |
| 订单与服务 | 预约、订单、履约、评价 | consumer / keeper | 本人/本村 | 是 | 云函数 |
| 审计 | 审计查询与留痕 | auditor | 全量只读 + 审计写 | 是（仅审计） | 云函数/内部 |
| 知识与检索 | 知识检索、引用 | 知识管家 | 审核后的知识域 | 否 | 内部工具 / MCP |
| Agent 编排 | 任务编排、状态、中断 | 系统 | 会话与任务 | 是（内部） | 长驻运行时，不对外 |
| 内容 | 内容草稿、审核、发布 | admin / 编辑 | 内容库 | 是 | 云函数；HTTP 可选 |

规则：

1. 一个接口只属于一个业务域，禁止跨域写；
2. 客户端传来的 `uid/role` 一律不可信，身份取云函数上下文或网关令牌；
3. 每个接口声明数据范围（本人/本村/全量）与读写属性；
4. 数据库写操作只能经领域服务/工具网关，禁止接口层拼 SQL。

## 三、云函数规范（范围 A，CloudBase）

### 3.1 命名与拆分

- 函数名 kebab-case：`<domain>-<capability>`，如 `roles-admin`、`plot-submit`；
- 一个函数只服务一个业务域，action 建议 ≤10 个；超出则拆分；
- 新函数 action 使用 `<domain>.<verb>`；
- 存量 `roles-admin` 的 action（`me/status/bootstrap/list/grant/revoke`）保留为**明确例外**，不再新增同类风格。

### 3.2 入参

```js
exports.main = async (event, context) => {
  // event.action: string
  // event.payload: object（新函数）；存量 roles-admin 直接读 event 字段
}
```

- 每个 action 用 Zod schema 校验 `event.payload`；拒绝未知字段；
- 身份只从 `cloudbase.getCloudbaseContext(context)` 读取 `TCB_UUID` / `TCB_CUSTOM_USER_ID`；
- 写操作必须携带幂等键（`idempotencyKey`）；
- 限制参数大小与数组长度，防止滥用。

### 3.3 返回包（项目统一）

```js
// 成功
{ ok: true, data: {...} }

// 失败
{ ok: false, code: 'AUTH_FORBIDDEN', message: '需要管理员权限', retryable: false, details?: {...} }
```

- **新函数**使用字符串错误码（如 `AUTH_FORBIDDEN`、`PLOT_DUPLICATE`）；
- **存量 `roles-admin` 使用数字码**（400/401/403/409/500/502/404）。这是已知例外，适配层负责映射为字符串码；迁移完成前不要混改；
- 不向客户端返回堆栈、SQL、内部路径；
- 全局 `try/catch` 兜底，返回统一失败包。

### 3.4 超时、重试与状态

- 云函数无状态，不依赖进程内缓存做业务判断；
- 写操作必须幂等；只有只读或幂等操作允许重试；
- 超时以云函数配置为准；长任务不在云函数内跑，交运行面/异步任务；
- 冷启动不影响正确性，只影响延迟。

### 3.5 日志与审计

- 结构化日志：`traceId`、`action`、`uid`（哈希）、耗时、错误码；
- 授权、交易、发布等敏感写操作必须写审计事件；
- 日志不得包含手机号、身份证、密钥。

### 3.6 HTTP 触发云函数（范围 B）

- 仅用于对外暴露；事件结构是 `path/httpMethod/headers/body/query`，**不是** `event.action`；
- 在适配函数内解析 HTTP → 调用领域服务 → 组装 HTTP 响应；
- 状态码、CORS、认证、限流在适配层处理；
- 禁止把 HTTP 事件直接透传给领域服务。

## 四、非云函数规范（范围 C/D/E/F）

### 4.1 外部 REST API

- OpenAPI 3.1 描述，路径 `/api/v1/<resource>`；
- 方法语义：GET 查询、POST 创建、PUT 全量更新、PATCH 部分更新、DELETE 删除；
- 状态码：200/201/204/400/401/403/404/409/422/429/500/503；
- 错误体使用 `application/problem+json`：`type/title/status/detail/instance/code/traceId`；
- 分页用 cursor；过滤/排序显式参数；写操作支持 `Idempotency-Key` 头；
- 认证用 Bearer/网关令牌；限流与配额在网关；
- 不得暴露云函数名、action、数字内部码。

### 4.2 MCP 工具

- 工具名 `<domain>.<verb>`，如 `pest.detect`、`knowledge.search`；
- 输入输出用 JSON Schema；标注 `readOnlyHint` / `destructiveHint`；
- 经工具网关鉴权、限流、审计；外部 MCP 必须代理，不直连；
- 不得把 REST 路径或云函数 event 作为工具参数。

### 4.3 Agent function calling

- 只暴露契约允许的工具子集；
- 写操作必须中断等人（interrupt）；
- 工具失败返回标准错误码，不让模型猜测；
- 所有调用记录 trace 与成本。

### 4.4 Webhook

- HMAC 签名 + 时间戳防重放；
- 事件 ID 幂等；
- 重试采用指数退避；失败进入死信。

## 五、适配层规则

| 职责 | 允许 | 禁止 |
| --- | --- | --- |
| 协议转换 | HTTP ↔ 云函数 event、MCP ↔ 契约 | 在适配层写业务规则 |
| 身份转换 | 上下文/令牌 → 契约身份 | 信任客户端 uid |
| 错误映射 | 数字码 ↔ 字符串码 ↔ HTTP 状态 | 吞掉错误或伪造成功 |
| 数据映射 | DTO ↔ 领域模型 | 直接查库、拼 SQL |
| 版本 | `/api/v1`、工具 schema 版本 | 无版本破坏性变更 |

## 七、验收清单

- [ ] 明确属于哪个业务域、哪个范围（A–F）；
- [ ] 契约 schema（Zod / JSON Schema）已定义；
- [ ] 身份来源正确（上下文/令牌），无客户端 uid；
- [ ] 数据范围与角色权限明确；
- [ ] 错误码符合规范（新函数字符串码；存量数字码已映射）；
- [ ] 写操作幂等；
- [ ] 审计与日志已埋点；
- [ ] 外部接口有 OpenAPI/MCP schema 与限流；
- [ ] 适配层有契约测试。

## 八、反模式

- 在 `callFunction` 里用 `event.path/httpMethod` 模拟 REST；
- 在外部 REST 里暴露 `action` 或云函数名；
- 新函数继续用数字错误码；
- 适配层直接查数据库或写业务规则；
- 一个云函数包揽多个业务域；
- 客户端传 `uid/role` 并采信；
- 长任务塞进云函数；
- 工具绕过网关直连第三方。
