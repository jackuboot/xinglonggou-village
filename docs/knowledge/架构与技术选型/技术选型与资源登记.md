# 技术选型与资源登记（v1.1）

> 阅读顺序与权威优先级：见本目录《00 · 阅读顺序与权威优先级》；冲突时按该文裁决。

> 结论先行：**不自研大模型**。默认调用现成模型 API/MCP，知识用 RAG，只有在本地评测证明不够用时才微调轻量视觉模型。

## 一、决策记录（ADR）

### ADR-001 不训练大语言模型
- 状态：已决定
- 理由：成本高、数据少、周期长；现成模型能力足够覆盖 P0；
- 后果：依赖外部模型服务，需要核验条款、数据出域与供应商锁定风险。

### ADR-002 默认使用神农大模型 4.0（API + MCP）
- 状态：待申请验证
- 理由：中国农大发布，1016 种病虫害、官方口径 93%+、支持方言交互，开放 API 与 MCP；
- 备选：农科小智（北京市农林科学院）；
- 待核实：商用条款、价格、限流、SLA、数据留存、本地口音效果。

### ADR-003 知识使用 RAG，不塞进模型参数
- 状态：已决定
- 方案：CloudBase PostgreSQL + pgvector；语料限政策原文、权威农技、村情审核条目；
- 规则：答案强制带引用；案例与推广稿不入库。

### ADR-004 条件性微调轻量视觉模型
- 状态：待触发
- 触发条件：本地 50–100 张实拍复测 Top-3 未达验收 85%。其中 **80–85% 先补本地数据、优化检索与提示词并复测；<80% 或主要病虫害不在覆盖内，触发微调**；
- 数据：AI Challenger 2018、IP102、PlantVillage、IDADP + 本地照片；
- 范围：只训视觉模型，不训大语言模型。

### ADR-005 TypeScript 优先与 Schema 单一来源
- 状态：已决定
- 方案：新增业务代码使用 TypeScript（`strict`）；Vue 3 + Vite 保持；Zod 统一运行时校验；Python 默认仅用于离线训练/评测（运行时回退须 ADR-007 单独评审）；
- 理由：类型与 schema 可被 AI、CI 与评审自动检查，命名与字段一致性才能强制执行；
- 后果：存量 JS 逐步迁移；新增 typecheck、lint、contract test 三类门禁；
- 详细规范见《工程规范与AI编程约定》。

### ADR-006 函数式与模块化约束
- 状态：已决定
- 方案：纯函数优先、副作用隔离；单文件 ≤1000 行（建议 ≤500）、单函数 ≤50 行、参数 ≤4；按 `domain/application/adapters/ui/shared` 分层，依赖单向；
- 理由：小文件与纯函数更利于 AI 增量修改、测试与审查；
- 后果：`max-lines`、`max-lines-per-function`、`import/no-cycle`、dependency-cruiser 纳入 CI；
- 详细规范见《工程规范与AI编程约定》。

### ADR-007 LangGraph 作为 Agent 编排运行时
- 状态：已决定（实现方式待 spike 验证）
- 方案：采用 **LangChain 生态**做模型/工具适配，**LangGraph 1.x** 做图编排与状态管理；优先 **LangGraph.js（TypeScript）**，与 ADR-005 保持一致；
- 能力：全局 State、Reducer、Postgres Checkpointer、interrupt 人工介入、time travel、按 `thread_id` 恢复；
- 边界：只允许出现在 `application/orchestration` 层，domain 保持框架无关；工具必须经工具网关白名单；
- 风险：部分高级容错能力（超时/错误处理）Python 版更靠前；LangGraph.js 在云托管容器中的流式/长任务与冷启动需验证；
- 回退：若 spike 证明 LangGraph.js 不满足，先评估同栈 Node 替代方案；必须使用 Python 服务时，需新增 ADR 并同步调整 ADR-005；
- 详细约定见《工程规范与AI编程约定》。

### ADR-008 请求面与 Agent 运行面分离（长驻运行时）
- 状态：已决定；承载方式待验证
- 方案：CloudBase 云函数只承载无状态请求（CRUD、鉴权、webhook）；Agent 运行在**长驻容器服务**（CloudBase 云托管优先，TKE 备选），支持 WebSocket/SSE；**进程内常驻是优化，会话连续性由检查点保证**；
- 会话模型：每个 `thread_id` 对应一个 **Actor**（单写者、邮箱串行、独立状态）；Redis/队列做邮箱与分布式锁，Postgres checkpointer 做恢复；
- 隔离：默认逻辑隔离（独立状态、独立邮箱、配额与背压）；高价值/监管场景可选独占实例；
- 缩容：云托管可缩容到 0；活跃会话保留最小实例，空闲会话落检查点后驱逐；
- 备选：腾讯云 Agent Runtime（状态与算力解耦、沙箱执行，需验证可用性与数据边界）；
- 理由：云函数生命周期短，无法承载长会话、流式交互与稳定进程；Agent 需要可恢复的状态与不被其他会话打断的执行流；
- 后果：新增运行时部署与运维；需要会话调度、背压、优雅下线与故障迁移。

### ADR-009 架构升级以预演结果为准
- 状态：已决定
- 方案：进入 S1/S2/S3 档位、更换运行时或模型前，必须完成容量、故障、成本三类预演；未达标不升级；
- 依据：《容量、稳定性与成本预演》（档位、SLO、成本公式、R-01~R-06 场景、升级触发条件）；
- 后果：增加预演工作量，但避免盲目扩容、成本失控与稳定性事故；
- 规则：预演数值未回填前，不得对外承诺容量、延迟或价格。

### ADR-010 AI 时代交付流水线（测试先行）
- 状态：已决定
- 方案：需求 → 数据结构 → 测试用例 → 纯函数业务 → AI 能力暴露 → E2E；P0 无用例不实现，测试不绿不合并；
- 能力形态：function calling / tool / skill / MCP，统一注册、网关与审计；
- 依据：《AI 时代架构与交付方法》；
- 后果：前期设计与用例评审时间增加，但 AI 生成代码的可验证性与稳定性显著提高。

### ADR-011 接口契约优先，传输适配
- 状态：已决定
- 方案：应用层定义 query/command 契约（TypeScript 类型 + Zod + 错误码）；前端主通道为 CloudBase `callFunction`；HTTP 网关与 MCP 仅作为外部/Agent 适配器；
- 理由：`callFunction` 是 CloudBase 原生方式，自带身份上下文、无需额外网关；REST 不是平台强制规范，只在外部集成时需要；
- 规则：业务逻辑只依赖契约，不依赖传输；适配器不承载业务规则；同一契约可映射到多种传输；
- 范围：云函数内部遵循 CloudBase 规范（`event.action`、上下文身份、统一返回包）；外部接口才使用 REST/OpenAPI/MCP；详见《接口规范与业务边界》；
- 后果：需要维护契约与适配器映射；接口规范不再以 REST 为唯一标准。
