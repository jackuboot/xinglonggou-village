# 容量、稳定性与成本预演（v0.2）

> 阅读顺序与权威优先级：见本目录《00 · 阅读顺序与权威优先级》；冲突时按该文裁决。

> 目的：在架构升级前先算清楚"要撑多少人、多少并发、多少钱、多少运维"，用压测与成本复盘校准，而不是凭感觉扩容。
> 说明：本文的并发、Token、单价均为**规划假设**，标注"待校准"的数值必须通过 spike/压测/账单验证。

## 一、设计目标（非功能）

| 目标 | 要求 | 验证方式 |
| --- | --- | --- |
| AI 易扩展 | 新增模型、工具、Agent 不改核心业务代码 | 模型网关 + 工具网关 + 契约卡 |
| 面向 AI 时代 | MCP/工具协议、评测集、成本计量、可回放 | 架构评审 + PoC |
| 客户量级 | 从 1 村到县域可平滑扩展 | 分档压测 |
| 并发 | 会话级隔离，单会话不拖垮整体 | 并发会话压测 |
| 稳定性 | 明确 SLO、RTO/RPO、降级路径 | 故障演练 |
| 一般成本 | 基础设施按量、可缩容 | 月度账单复盘 |
| AI 成本 | 单次会话/单张图片成本可计量、可限额 | Token/调用计量 |
| 运维难度 | 优先托管服务，减少自建组件 | 运维人天统计 |

## 三、容量模型

### 3.1 会话与算力

单会话负载 = 每条消息的步数 × 每步工具调用数 × 模型 Token。

- 规划假设：平均每条消息 6 步、每步 1.5 次工具调用、每步输入 2k tokens / 输出 500 tokens（待校准）；
- 单实例承载：按 **10–20 个活跃会话/实例（1 vCPU / 2GB）** 估算，必须用压测校准；
- 扩容公式：`所需实例数 = 峰值并发会话 ÷ 单实例会话数 × 1.3（冗余）`。

### 3.2 存储与检查点

- 每步检查点大小约 20–100 KB（含消息与工具结果，待校准）；
- 单会话 20 步约 0.4–2 MB；
- 日 1,000 会话约 0.4–2 GB/天，需设置保留期与归档策略；
- 向量库：每千条知识条目约 1–5 MB（含分块与索引，待校准）。

### 3.3 队列与事件

- 每会话每步 1 条内部消息 + 0.5 条业务事件（假设）；
- S1 峰值约 20 会话 × 2 步/分钟 ≈ 40 消息/分钟，云函数/轻量队列足够；
- 超过 100 事件/秒或需要回放时，升级 CKafka/TDMQ。

## 四、稳定性目标（SLO）

| 指标 | S0–S1 目标 | S2+ 目标 | 说明 |
| --- | --- | --- | --- |
| 官网/工作台可用性 | 99.5% | 99.9% | 静态托管 + 云函数 |
| Agent 会话成功率 | ≥95% | ≥99% | 含模型失败与工具失败 |
| API P95 延迟 | ≤500 ms | ≤300 ms | 不含 AI 推理 |
| 首 Token 延迟 | ≤3 s | ≤2 s | 流式输出 |
| 完整回答 P95 | ≤30 s | ≤20 s | 含工具调用 |
| 会话恢复时间 | ≤5 s | ≤3 s | 从检查点重建 |
| 错误率 | ≤1% | ≤0.5% | 5xx + 业务失败 |
| RTO / RPO | 1 h / 5 min | 30 min / 1 min | 检查点与备份 |

## 五、成本模型（结构 + 公式）

### 5.1 成本构成

| 类别 | 构成 | 计量单位 | 备注 |
| --- | --- | --- | --- |
| 基础设施 | 云托管实例、数据库、存储、队列、CDN | 小时 / GB / 请求 | 按量计费，可缩容 |
| AI 推理 | 问答 Token、图片识别次数、ASR 分钟、Embedding | Token / 次 / 分钟 | 单价以服务商报价为准 |
| 运维 | 值守、巡检、故障处理、发布 | 人天/月 | 托管越多，人天越少 |

### 5.2 计算公式

```
月 AI 成本 =
  问答会话数 × 每会话 Token × 单价(Token)
+ 病虫害图片数 × 单价(张)
+ 语音分钟数 × 单价(分钟)
+ 知识入库 Chunk 数 × 单价(Embedding)

月基础设施成本 =
  最小实例数 × 服务时长 × 实例单价
+ 数据库规格 × 时长
+ 存储量 × 单价
+ 队列/向量库用量 × 单价

单次有效服务成本 = 月总成本 ÷ 月有效服务次数
```

### 5.3 成本控制线

1. 每个 Agent 契约卡设 Token 与调用预算；
2. 单会话最大步数、最大工具调用次数；
3. 模型分级路由：常规任务小模型，复杂任务大模型；
4. 缓存高频问答与知识检索结果；
5. 超过预算 120% 告警，超过 150% 自动降级到小模型。

> 不在文档中写死单价；首次预演后用真实账单回填，形成"单次服务成本"基线。

## 六、运维难度与成本

| 档位 | 运行形态 | 运维关注点 | 估算人天/月 |
| --- | --- | --- | --- |
| S0 | CloudBase 云托管 + 云函数 | 发布、日志、少量告警 | 2–4 人天 |
| S1 | 同上 + 监控看板 | 会话恢复、模型降级、成本 | 4–8 人天 |
| S2 | 云托管多实例 + TKE 评估 | 扩缩容、队列、租户隔离 | 10–20 人天 |
| S3 | TKE / Agent Runtime + 专用运维 | 容量规划、故障演练、合规 | 30+ 人天 |

## 七、预演与压测（升级前必做）

| 编号 | 场景 | 方法 | 通过标准 |
| --- | --- | --- | --- |
| R-01 | API 峰值 | k6/Artillery 打 CRUD 与检索接口 30 分钟 | P95 达标、错误率 ≤1% |
| R-02 | 并发会话 | 模拟 20/100/500 个 LangGraph 会话，各 10 步 | 无串话、成功率 ≥95% |
| R-03 | 故障恢复 | 中途杀掉 20% worker | 会话 5 秒内恢复、无重复副作用 |
| R-04 | 模型降级 | 注入 10% 超时/限流 | 自动切换备用模型，成功率 ≥95% |
| R-05 | 成本计量 | 跑 100 个真实会话与 100 张图片 | 得出单会话/单张成本 |
| R-06 | 租户隔离 | 两个村的数据交叉访问 | 100% 拒绝，审计留痕 |

**预演节奏**：进入 S1/S2/S3 前各做一次；重大模型或运行时变更后重跑 R-02/R-03/R-05。

## 八、架构升级触发条件

| 组件 | 当前 | 升级为 | 触发条件 |
| --- | --- | --- | --- |
| 向量检索 | pgvector | 腾讯云向量数据库 | 知识块 >10 万，或检索 P95 >300 ms |
| 事件总线 | 云函数/触发器 | CKafka / TDMQ | >100 事件/秒，或需要回放 |
| 运行时 | CloudBase 云托管 | TKE / Agent Runtime | 最小实例 >5，或需要严格会话亲和 |
| 模型 | 现成 API | 本地/微调视觉模型 | 本地 Top-3 未达验收 85%（<80% 直接微调；80–85% 先补数据） |
| 多租户 | 单村 `village_id` | 独立库/独立实例 | 进入 S2 且数据隔离要求提升 |

## 九、待校准假设（必须用预演回填）

1. 单实例可承载的活跃会话数；
2. 每会话平均步数与 Token；
3. 检查点平均大小与增长；
4. 各模型/ASR/图片识别的真实单价；
5. 单次有效服务成本与预算上限；
6. 云托管最小实例的常驻成本。

> 预演结果回填后，更新本文件版本与档位阈值；未经验证的数值不得写进对外承诺。
