## D-01 LangGraph.js 与 Python 版的能力差异

**决策：默认采用 LangGraph.js（TypeScript）。** Python 不作为并行选项，只有在下述验收失败时才启用，且必须新增 ADR、同步修改 ADR-005 的 Python 边界。

**Spike 验收（缺一不可）**：

1. PostgreSQL checkpointer 写入与按 `thread_id` 恢复；
2. `interrupt` 暂停 → 人工审批 → resume 全流程；
3. 云托管容器内的 SSE/WebSocket 流式输出；
4. 20 个并发会话无串话、无状态污染；
5. 空闲实例回收后，会话能在 5 秒内从检查点恢复。

**失败处理**：任一项不通过，先评估同栈 Node 替代方案；仍不满足才启用 Python 服务，并新增 ADR。

**责任人 / 时间**：AI 工程师，下周内完成 spike。

**状态**：已决策（条件关闭，待 spike 验证）。

## D-02 云托管最小实例、冷启动与常驻成本

**决策**：

- 服务时段保留 **1 个最小实例**，规格从最小粒度 **0.25 核 / 0.5GB** 起步；
- 非服务时段允许缩容到 0，不产生计算费用；
- 会话不依赖进程常驻：每步落检查点，实例回收后按 `thread_id` 重建；
- 网关按 `thread_id` 做粘性路由，尽量命中同一实例；
- 设置月度预算上限与费用告警；单价以腾讯云购买页为准，不在文档中写死。

**重要限制**：CloudBase 云托管的定位是**无状态容器服务**，实例空闲 30 分钟会被回收（最小实例为 0 时）。因此"进程内常驻"只是优化，**真正的会话连续性由检查点保证**。如果后续要求严格的进程亲和或长时间不回收，迁 TKE 或腾讯云 Agent Runtime。

**状态**：已决策（待账单与压测验证）。

## D-03 roles-admin 旧 action 与新 API 规范的过渡

**决策：旧接口冻结，新增 REST 门面，双轨运行两个版本后弃用。**

| 旧 action | 新接口 | 说明 |
| --- | --- | --- |
| `me` | `GET /api/v1/users/me/roles` | 当前用户授权 |
| `status` | `GET /api/v1/system/status` | 系统状态 |
| `list` | `GET /api/v1/users?include=roles` | 管理员列表 |
| `grant` | `PUT /api/v1/users/{uid}/roles` | 授予/修改角色 |
| `revoke` | `DELETE /api/v1/users/{uid}/roles` | 撤销授权 |
| `bootstrap` | `POST /api/v1/system/bootstrap` | 仅部署端，带一次性令牌 |

**规则**：

1. 过渡期内旧 action 只修 bug，不新增能力；
2. 新前端只调用 REST；旧调用由适配层转换；
3. 错误码统一映射到新规范（如 `AUTH_FORBIDDEN`、`PLOT_*` 等）；
4. 两个发布版本后，确认无调用方再下线旧 action；
5. `bootstrap` 继续保持"无用户上下文 + 仅首次"双准入。

**状态**：已决策（实现阶段执行）。
