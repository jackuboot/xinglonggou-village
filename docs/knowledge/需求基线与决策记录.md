# 需求基线与决策记录（v0.1）

> 用途：沉淀需求变更与关键决策，避免"口头定了、事后找不到依据"。每条需求或决策单独成条，按时间倒序追加。

## 一、需求条目模板

| 字段 | 说明 |
| --- | --- |
| 需求编号 | REQ-YYYY-NNN |
| 提出人 / 来源 | 村委、农户、审计、运营反馈 |
| 使用场景 | 谁在什么情况下要用 |
| 痛点 | 现在的做法与损失 |
| 目标与验收口径 | 可度量的完成标准 |
| 优先级 | P0/P1/P2（依据蓝图 7.1） |
| 关联 Agent / 模块 | 农户助手、预警哨兵等 |
| 状态 | 待评审 / 已立项 / 开发中 / 已验收 / 搁置 |
| 决策记录 | 结论、理由、责任人、日期 |

## 四、变更规则

1. 新增或变更 P0 需求需产品 Owner 与审计员双签；
2. 影响门禁指标的需求变更，必须同步更新《阶段门禁与里程碑》；
3. 被搁置的需求保留记录与原因，不删除；
4. 涉及隐私、对外发布、资金/交易的需求，必须附合规评估。
