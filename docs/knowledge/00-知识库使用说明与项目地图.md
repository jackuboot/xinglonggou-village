# 知识库使用说明与项目地图（v0.1）

> 用途：说明 QMind 知识库的组织逻辑，以及一个系统级产品从立项到运营各阶段该产出什么、放在哪里。
> 边界：QMind 是**策展型资料库**，只收录显式添加的内容，不会自动归档；代码与架构知识由 Qoder 知识中心的 Repo Wiki 自动维护，两边不重复。

## 一、系统级产品的九个阶段与目录对应

| 阶段 | 要回答的问题 | 对应目录 | 关键产出 | 门禁 |
| --- | --- | --- | --- | --- |
| 1 立项与愿景 | 为什么做、做到什么程度 | 项目治理与路线图 | 蓝图、范围、成功指标、干系人 | 蓝图评审通过 |
| 2 需求与调研 | 谁在用、真实痛点是什么 | 需求与沟通记录、村情调研、政策文件 | 村情基线、访谈纪要、政策约束清单（资源/服务数据由产品提交产生） | 需求基线确认（村委签字） |
| 3 产品定义 | 先做什么、怎么验收 | 需求与沟通记录 | PRD、场景优先级、验收口径 | 优先级评审通过 |
| 4 架构与选型 | 用什么实现、边界在哪 | 架构与技术选型 | ADR、资源登记、接口清单、安全设计 | 选型评审通过 |
| 5 数据与模型 | 数据够不够、模型能不能用 | 数据与知识资产 | 数据字典、数据集许可、标注规范、知识条目 | 数据就绪度检查 |
| 6 开发与集成 | 怎么把 Agent 嵌进业务 | 项目治理与路线图（计划）；代码文档见 Repo Wiki | 契约卡、接口联调、审计埋点 | 联调通过 |
| 7 测试与评测 | 是否达标、错在哪 | 测试与评测 | 评测集、评测报告、缺陷清单 | 门禁指标达标 |
| 8 部署与运营 | 怎么稳定运行、怎么改进 | 部署与运维、运营与反馈 | 运行手册、监控看板、复盘记录 | 稳定运行 4 周 |
| 9 交付与归档 | 交付了什么、下一步是什么 | 交付与汇报 | 汇报材料、版本记录、阶段总结 | 阶段复盘通过 |

## 二、目录职责（现有 11 个）

| 目录 | 放什么 | 不放什么 |
| --- | --- | --- |
| 项目治理与路线图 | 阶段门禁、里程碑、决策记录、风险 | 具体需求细节 |
| 需求与沟通记录 | 需求、会议纪要、决策背景、变更 | 交付成稿（放交付与汇报） |
| 村情调研 | 村情基线、调研提纲、访谈记录 | 地块/产品/服务等资源数据（由农户在业务系统自助提交） |
| 政策文件 | 政策原文、索引、合规要求 | 二手解读当原文 |
| 设计与竞品参考 | 参考案例、设计灵感（**仅存档**） | 作为蓝图依据或验收标准 |
| 架构与技术选型 | 架构文档、ADR、资源与接口登记 | 代码实现细节（Repo Wiki） |
| 数据与知识资产 | 数据字典、数据集、许可、标注规范、知识条目 | 来源不明或未授权数据 |
| 测试与评测 | 评测集、评测方案、报告、缺陷 | 只有结论没有证据的记录 |
| 部署与运维 | 运行手册、环境、监控、故障处置 | 业务需求 |
| 运营与反馈 | 指标、反馈、复盘、迭代记录 | 原始用户隐私数据 |
| 交付与汇报 | 蓝图、PPT、报告、版本归档 | 过程草稿 |

## 三、录入规则

1. 一主题一文档，命名建议 `YYYY-MM-DD-主题-版本.md`；
2. 每条事实标注来源与日期；事实、假设、案例三类分开标注；
3. 案例与竞品只存档，不作为需求依据；推广稿不得作为数据引用；
4. 涉及手机号、身份证、住址等个人信息一律脱敏；
5. 未核实内容标注"待核实"，核实后更新版本号。

## 四、当前状态（2026-10）

- 已完成：蓝图 v0.1、汇报 PPT v0.1、政策索引、调研提纲、技术选型登记、数据资产登记、P0 评测方案、部署索引、指标闭环；
- 未启动：农户自助提交 MVP、方言语料与病虫害照片采集、神农 API 申请、P0 PoC、监控看板；
- 最大缺口：**供给端提交闭环尚未上线**；资源与服务数据由农户注册后自助提交，不做事前集中采集；村情基线仍需少量调研补充。

## 五、维护节奏

- 每周五：整理本周新增资料，归入对应目录；
- 每月：政策巡检一次（失效链接、新版本）；
- 每阶段结束：归档一版交付物，更新门禁状态。
