## 三、监控与告警

| 监测点 | 阈值 | 动作 |
| --- | --- | --- |
| Agent 任务成功率 | <95% | 告警 + 排查模型/工具 |
| 人工接管率 | 周环比 +50% | 复盘知识缺口或模型退化 |
| 工具失败率 | >5% | 检查第三方 API 与网络 |
| P95 时延 | >30s | 检查模型路由与队列 |
| 单日 token 成本 | >预算 120% | 限流/降级到小模型 |
| 敏感操作 | 越权/未审批 | 立即阻断 + 审计 |

## 四、故障处置

1. 回滚：恢复上一版本静态包/云函数版本；
2. 降级：将对应 Agent 从 L2/L3 降到 L1（只读建议），或切换备用模型；
3. 隔离：关闭问题工具的白名单权限，保留审计证据；
4. 密钥：怀疑泄露时立即轮换，并检查调用日志；
5. 通知：按影响范围通知管理员、审计员与村委。

## 五、安全约定

- 身份只信云函数上下文 `TCB_UUID`，前端传参不可信；
- Agent 权限 = 人类角色权限 ∩ 契约卡范围；
- 审计日志只增不改，第三方调用需记录数据出域范围；
- 环境 ID、路径不要在多个文件重复硬编码（已知风险）。

## 六、已知风险

- 单一 CloudBase 环境，无跨环境备份策略；
- 部署脚本与环境 ID、tcb CLI 路径存在硬编码；
- 监控与审计 schema 尚未落地；
- 官网 Qoder Sites 与 CloudBase 双部署，主域名未定，存在内容不同步风险。
