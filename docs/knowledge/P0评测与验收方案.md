# P0 评测与验收方案（v0.1）

> 目的：用最小成本回答一个问题——**现成模型在我们的真实场景里够不够用**。够用就上线，不够用才微调。

## 一、评测对象

| 场景 | 被测对象 | 对照 |
| --- | --- | --- |
| 病虫害拍照识别 | 神农 4.0（API/MCP） | 农科小智 / 通用多模态模型 |
| 方言语音农技问答 | 神农方言交互 + RAG | 腾讯云 ASR + 通用 LLM |
| 入库质检助手 | 拍照 + 标准知识库 | 人工质检基线 |
| 官网内容助手 | 农户故事 → 文案草稿 | 人工撰写基线 |

## 二、评测数据

- **病虫害照片**：50–100 张本地实拍，覆盖主要作物与主要病害；标注规范见《数据资产与许可登记》；
- **农技问题**：20–30 条真实问题，含老人表达与方言转写；
- **质检样本**：10–20 笔真实入库记录（脱敏）；
- **内容样本**：5–10 段农户故事素材。

## 三、指标与门禁

| 场景 | 指标 | 阈值 | 判定方式 |
| --- | --- | --- | --- |
| 病虫害识别 | Top-3 召回 | ≥85% | 本地照片 + 专家复核 |
| 病虫害识别 | 专家复核一致率 | ≥80% | 农技专家盲评 |
| 语音问答 | 方言字错率（田间噪声） | ≤15% | 人工转写对比 |
| 语音问答 | 引用率 | ≥95% | 答案必须带来源 |
| 语音问答 | 不安全回答率 | ≤0.5% | 用药/纠纷类专项检查 |
| 入库质检 | 单笔录入耗时 | 下降 ≥30% | 计时对比 |
| 入库质检 | 异常检出覆盖率 | ≥95% | 已知异常样本 |
| 官网内容 | 草稿采纳率 | ≥60% | 人工审核记录 |
| 官网内容 | 合规退回率 | ≤10% | 审核记录 |

## 四、执行流程

1. 申请神农 API/MCP，核验条款（W1）；
2. 采集本地样本并完成标注（W2）；
3. 跑基线：每个场景记录原始输入、模型输出、耗时、成本（W3）；
4. 误差分析：按作物/病害/方言/场景聚类错误（W3–W4）；
5. 决策：达标 → 进入常态化使用；不达标 → 进入条件微调（W4）；
6. 复测并更新本报告。

## 五、证据要求

- 每次评测保留：原始输入、模型版本、调用时间、输出全文、评审人、结论；
- 不得只记录"通过/不通过"，必须有可复核的证据；
- 涉及第三方的结果，注明服务提供方与调用参数。

## 六、时间表

| 周 | 任务 | 产出 |
| --- | --- | --- |
| W1 | 申请与条款核验 | 接入结论 |
| W2 | 样本采集与标注 | 评测集 v0.1 |
| W3 | 基线评测 | 评测报告 v0.1 |
| W4 | 误差分析与决策 | 决策记录（API/微调） |

## 七、非目标

- 不追求实验室精度，不引用厂商宣传值；
- 不在 P0 做全量上线；
- 不用案例数据替代本地评测。
